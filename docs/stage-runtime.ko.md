# 스테이지 제작과 실행 · 0.4.0

## 작업 파일

마인크래프트 폴더와 별개인 작업 폴더를 정합니다.

```text
내 작업 폴더/
  tile/
    연구소/
      진입실.nbt
      복도.nbt
    공장/
      복도.nbt
  stage/
    첫 탐사.esfile
    다음 탐사.esfile
```

스테이지는 편집 가능한 프로젝트이기도 합니다. `.esfile` 하나가 작성자·챕터명·난이도·스테이지 이름·설명, 타일 참조, 배치, 구역, 기믹, 목표와 이벤트 블록을 모두 보관합니다. 내부에는 다섯 JSON 설정만 있고 NBT는 들어가지 않습니다. `연구소/복도.nbt`와 `공장/복도.nbt`는 다른 타일입니다. 저장 당시 SHA-256과 크기도 검사하므로 원본이 바뀌었다면 편집기에서 명시적으로 설계도를 교체하세요.

## 만드는 순서

1. 첫 화면에서 **새 스테이지 만들기** 또는 **기존 .esfile 불러오기**를 선택합니다. 브라우저에 이전 작업이 있으면 복원할 수도 있습니다.
2. **타일 폴더 연결**에서 위 구조의 `tile` 폴더를 선택합니다. 가져온 타일은 타일셋 폴더별로 표시됩니다.
3. 타일을 선택하고 **설계도 미리보기**로 구조를 확인합니다. **설계도 보기 → 설계도 열기**는 규격·문 검사를 통과하지 않는 일반 구조물 NBT도 단일 조회합니다. 실제 블록 좌표를 사용하지만 외형은 간단한 색상 육면체입니다. Create의 복잡한 모델과 텍스처·작동을 재현하지 않습니다. 표시 높이를 낮추면 천장을 잘라 내부를 볼 수 있습니다.
4. 평면/입체 배치도에서 타일을 연결합니다. 배치도에서는 크기와 문 위치를 사용합니다. 소속 구역과 a/b/c 하위 구역을 정하고 층을 전환합니다. X/Z는 1블록, Y는 8블록 단위입니다. 실제 비공기 블록 충돌은 허용하지 않습니다.
5. 기믹 탭에서 **시작점**과 **탈출 지점**을 적어도 하나씩 둡니다. 시작점은 진입 텔레포터입니다. 실물 장치의 내부 좌표는 빈 셀 또는 같은 장치 블록이어야 합니다. 패드 윗부분에 사람이 설 공간과 바닥을 준비하세요.
6. **임무 목표**에서 ‘필수 목표 완료 후 탈출’ 또는 ‘탈출 자체가 목표’를 선택합니다. 목표 종류는 터미널 명령어, 타일 방문, ID 키카드 획득, 화물 들기, 화물 운반, 이벤트로 완료입니다. 선택 목표도 지정할 수 있습니다.
7. 이벤트 탭에서 발생·조건·흐름·실행 블록을 연결합니다. 검사 오류를 고치고 **스테이지 저장**으로 `stage` 폴더에 `.esfile`을 저장합니다. 진행 중 초안도 저장할 수 있습니다. `runtimeReady`는 연결·목표·원본 참조 검사를 통과했는지 표시합니다.

폴더 읽기는 Chrome·Edge·Firefox의 폴더 입력을 사용합니다. 웹 앱은 파일을 서버에 업로드하지 않습니다. 폴더에 직접 쓰는 기능은 없으므로 다운로드 위치로 `stage` 폴더를 고르세요. 자동 저장은 브라우저 안의 보조 복원본이며 원본 파일을 자동으로 덮어쓰지 않습니다.

## 터미널과 수집품

- **시설 터미널**은 명령어 입력 전용입니다. `HELP`는 명령어 목록, `STATUS`는 목표·알람 현황입니다. 위·아래 방향키로 이전 입력을 고르고 휠로 기록을 봅니다. 허용 명령어는 한 줄에 하나씩 입력하며, 목표·이벤트에 연결된 명령어도 자동 허용합니다. 대소문자와 연속 공백은 정규화합니다. 임의 Minecraft 명령어는 실행하지 않습니다.
- **보급 컨테이너**는 9칸입니다. 설계도에 저장된 기존 내용물은 유지합니다. 현재는 별도 키카드 기믹에서 이 컨테이너를 선택해 넣을 수 있습니다. 모드 0.4.5부터 탄약·체력 보급 팩 수량을 지정할 수 있습니다. 각 팩은 4개씩 겹쳐 들어가며 기존 물건·키카드 자리를 포함해 9칸 안에 들어가야 합니다. 팩을 손에 들고 E를 1초 유지해 사용합니다. 체력 팩은 기본 하트 4칸, 탄약 팩은 주·보조무기의 별도 예비탄을 보급합니다. 무작위 추첨 규칙은 다음 작업 범위입니다.
- **ID 키카드**는 일반 아이템처럼 수집합니다. 컨테이너를 지정하지 않으면 해당 위치에 아이템으로 둡니다. 목표·이벤트는 같은 이름의 다른 물건이 아니라 고유 기믹 ID를 추적합니다.
- **화물 상자**는 CarryOn이 필요합니다. 양손을 비우고 상자를 조준해 **E를 1초 유지**합니다. 기존 CarryOn의 바로 들기로 이 시간을 건너뛸 수 없습니다. 내려놓기는 CarryOn의 즉시 배치를 그대로 사용합니다. 들어 올려도 고유 기믹 ID가 유지됩니다. 화물 운반 목표는 든 채 탈출 지점 반경에 도달하면 완료됩니다.
- E키는 총을 들고도 터미널·보급함·문을 조작합니다. 화물 운반만 CarryOn 규칙 때문에 양손을 비워야 합니다. F키 손전등과 기존 문 조작은 유지됩니다.

## 보안 알람

알람은 문과 독립된 기믹입니다. ‘보안 문을 열려고 하면’, ‘터미널 명령어를 입력하면’, ‘화물을 들어 올리면’, ‘ID 키카드를 획득하면’ 같은 발생 블록에서 **경보 시작** 실행 블록으로 연결합니다. 조명 제어와 문 닫기도 같은 실행 목록에 섞을 수 있습니다.

알람 설정은 두 동작을 함께 제공합니다.

- 선택한 숫자 구역에 있는 몹의 대기를 해제합니다. 대기 몹 기믹으로 만든 몹은 AI가 멈춘 채 시작합니다.
- 새 몹은 **문 연결의 최단 거리** 또는 **직접 지정한 배치 타일**에 생성합니다. 거리 2는 문 연결을 두 번 건너가는 타일입니다. 좌표상 가까운 타일은 기준이 아닙니다. 기준점은 발생 이벤트의 타일이며 스테이지 시작·이름 신호처럼 출처가 없는 이벤트는 알람 기믹의 타일입니다.

횟수·생성 간격·타일별 수량을 지정합니다. 한 회 전체 64마리, 세션 전체 동시 소유 엔티티 512개로 제한합니다. 무작위로 선택한 타일 안에서 바닥과 충돌 여유가 있는 위치를 찾아 생성합니다. 바닥이 없거나 공간이 좁으면 생성하지 못할 수 있으므로 실제 타일에서 확인하세요. 알람은 모든 회차와 대상 몹 처치가 끝나거나 지정 시간이 지나면 종료됩니다. 이미 진행 중인 알람의 재시작 요청은 무시합니다.

문 양쪽의 접근 조건은 독립적입니다. 예를 들어 바깥쪽 문 시도 → 알람 시작 → 알람 종료 → 바깥쪽 면 잠금 해제로 연결하고 안쪽 면은 조건 없음으로 둘 수 있습니다. 잠금 해제 후에도 보안 문 열기는 E 1초이며, 닫기는 별도 터미널 이벤트·기믹으로 제어합니다.

## 게임에서 실행

모드 0.4.0 이상이 필요하며 화물을 쓴다면 CarryOn도 설치합니다. 타일에 사용한 다른 모드들도 게임에 있어야 합니다. 관리자는 다음 명령으로 작업 폴더를 한 번 지정합니다.

```text
/erosionsector stage workspace C:\내작업폴더
/erosionsector stage list
/erosionsector stage check 첫 탐사.esfile
/erosionsector stage start 첫 탐사.esfile
```

경로는 공백을 포함해 입력할 수 있습니다. 작업 폴더 안에 `tile`과 `stage`가 있어야 합니다. 서버는 설정 묶음·원본 해시·블록 설치 여부·실제 겹침을 확인하고, 임무 전용 차원에 이전 배치를 정리한 다음 스테이지를 만듭니다. 실제 문 연결도 배치 후 확인합니다. 준비가 완료되기 전에는 참가자를 이동하지 않습니다.

로비에 가입한 파티는 방장이 출발합니다. 로비에 가입하지 않은 플레이어는 솔로 검사가 가능합니다. 로비 밖 시설 터미널에서도 `STAGES`와 `DEPLOY 파일명.esfile`을 입력할 수 있습니다. 서버당 동시 임무는 하나입니다. 준비 상태·장비 지급을 완성한 정식 로비 출발 UI는 이후 확장할 수 있으며 현재 출발은 위 명령/터미널을 사용합니다.

텔레포터 탈출은 반경 안에 모여 E로 작동합니다. 스캔 탈출은 실제 스캔 패드 위에 대원 한 명이 서 있고 설정한 시간 동안 조건을 유지해야 합니다. 기본적으로 생존한 동료 모두가 반경 안에 있어야 합니다. 목표 임무는 필수 목표 완료 후 활성화되고, 이벤트로 직접 활성화할 수도 있습니다.

성공·실패 시 원래 차원·위치·게임 모드로 복귀합니다. 방장이 연결을 종료하거나 생존 대원이 없어지면 실패합니다. 진행 중 세션은 재접속 복구하지 않습니다. 결과는 작업 폴더의 `results`에 JSON으로 남습니다. 기존에 논의한 외부 웹 기록 서버·무료 DB 업로드는 이 로컬 실행 기능과 별개이며 여기에는 연결하지 않았습니다.

## 한도와 검증

타일 각 축 256블록, 타일당 저장 블록 25만, 스테이지 실제 블록 100만·청크 512개입니다. NBT 원본은 파일당 24MB·합계 64MB, NBT 압축 해제 64MB, `.esfile` 압축/해제 설정은 각각 64MB입니다. 이벤트는 300개·블록 5000개·중첩 12단계, 반복 100회까지입니다. 대기는 20틱/초를 기준으로 하며 서버가 느려지면 실제 시간도 늘어납니다.

`npm test`는 파일·배치·목표·이벤트와 미리보기 메쉬를 검사합니다. `npm run test:browser`는 새로 만들기·불러오기·폴더·목표/알람 설정·미리보기·저장 및 모바일 흐름을 검사합니다. `node tools/runtime-fixture.mjs <폴더>`는 모드 통합 검사에 쓰는 실제 `.esfile`과 NBT 작업 폴더를 만듭니다. 이 검증 시설은 완성된 튜토리얼 스테이지가 아닙니다.
