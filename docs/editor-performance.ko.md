# 편집기 성능 최적화

## 변경한 부분

- 프로젝트가 바뀔 때 타일·배치·구역 검색표, 회전된 타일 경계, 입체 보기의 기준점, 상자 점유 위치를 한 번 구성합니다. 지도 이동·확대·드래그 미리보기는 이 정보를 재사용합니다.
- 같은 블록 안에서 움직이는 드래그 미리보기는 직전 결과를 재사용합니다. 타일·회전·구역·층·블록 위치가 달라지면 다시 계산합니다. 최종 드롭도 다시 검사합니다.
- 편집·불러오기·실행 취소·다시 실행은 프로젝트 개체를 교체합니다. 검색 정보는 이 변경을 기준으로 새로 구성합니다. 타일 원본 연결과 회전 변경 역시 새 정보가 적용됩니다.
- 변하지 않은 확대 배율·커서 좌표·시점·드롭 안내를 화면에 반복해서 쓰지 않습니다. 배치 성공 시 전체 화면 재구성도 한 번으로 줄였습니다.
- 편집 시 새 작업용 사본 한 개를 만들고 검증합니다. 이전 정상본은 그대로 실행 취소 목록에 보관합니다. 기존의 전체 복사 3회를 1회로 줄였으며, 자동 저장의 추가 수동 복사도 제거했습니다. IndexedDB 자체의 저장 시 복사와 외부 파일 불러오기의 입력 보호 복사는 유지합니다.

파일 형식·배치 규칙·충돌 판정·실행 취소 횟수·자동 저장 방식은 유지합니다. 캐시는 `.esfile`이나 자동 저장 데이터에 포함하지 않습니다. 모드 JAR 및 외부 모드는 수정하지 않았습니다.

## 측정

같은 컴퓨터에서 이전 코드와 최적화 코드를 `tools/benchmark-editor.mjs`로 실행했습니다. 타일 종류 200개, 배치 100/500/1,000개, 배치당 컨테이너 3개인 합성 장면입니다. 아래는 타일의 서로 다른 위치 30곳을 검사하는 배치 처리 시간의 중앙값입니다.

| 배치 수 | 이전 | 최적화 후 |
|---|---:|---:|
| 100 | 2.184 ms | 0.497 ms |
| 500 | 7.396 ms | 0.649 ms |
| 1,000 | 15.875 ms | 0.724 ms |

이는 **검색 정보가 준비된 뒤의 미리보기 계산** 측정입니다. 첫 검색 정보 구성, 화면 그리기, UI 재구성, 파일 읽기 시간을 포함하지 않습니다. 전체 화면 FPS가 같은 비율로 빨라진다는 뜻은 아닙니다. 측정값은 컴퓨터와 입력 데이터에 따라 달라집니다.

현재 코드 측정:

```
node tools/benchmark-editor.mjs
```

이전 버전의 모듈 사본을 같은 디렉터리 구조로 준비했다면 그 디렉터리를 인자로 지정해 동일한 계산을 비교할 수 있습니다. 벤치마크는 사용자 스테이지를 읽거나 변경하지 않습니다.

## 검증 범위

캐시 사용·미사용 결과를 회전·층·블록 점유·편집·실행 취소 조건에서 비교합니다. 실제 브라우저에서 대형 장면의 반복 검색 제거, 드롭 후 화면 갱신 횟수, 드래그 배치와 저장, 실행 취소·다시 실행, 자동 저장 후 재접속 복구도 검사합니다.
