# 모드 최적화

## 0.5.2

- 정지한 문의 목표 개폐 상태는 매 틱 전체 순회하지 않습니다. ES 문에서 개폐 요청·조립·로드·제거·방향·결합 상태가 바뀔 때 월드별 변경 번호를 올리고, 스테이지가 변경된 경우에만 문 목록을 확인합니다. 한 틱의 여러 변경을 마지막 상태 하나로 판정하는 기존 이벤트 순서는 유지합니다.
- 이벤트 규칙은 시작할 때 발생 종류와 대상으로 분류합니다. 복합 조건의 모든 하위 신호를 등록하되 같은 신호는 중복 등록하지 않습니다. 원래 규칙 순서와 `모두 충족`의 누적 상태, 한 번만 실행, 반복·대기와 기존 실행량 제한은 유지합니다.
- 변경되지 않은 키카드는 불변 CustomData를 기준으로 식별 결과를 재사용해 매 틱 NBT를 복사하지 않습니다. 캐시는 세션당 128개로 제한합니다. 슬롯 확인은 유지합니다. Minecraft의 `Inventory.setItem`이나 다른 모드의 컴포넌트 교체가 항상 `setChanged`를 호출하는 것은 아니므로, 인벤토리 변경 횟수만으로 수집 검사를 생략하지 않습니다. 변경 알림 없는 컴포넌트 교체도 같은 틱에 인식하는 검사로 확인합니다.

기본 GameTest 147개에 복합 신호의 중복·순서·상태·반복, 문의 정지·신호 개폐·같은 틱의 최종 상태와 직접 교체한 키카드 검사를 포함했습니다. 설치된 TaCZ 연동 6개와 CarryOn 화물 인계 1개도 통과했습니다. 실제 스캔 클라이언트에서 목표 완료·문 잠금 해제·탈출 후 차원 복귀를 확인했습니다. 그래픽 품질·조명 값·갱신 주기는 바꾸지 않았습니다.

### 모사 부하 측정 · 2026-10-18

숨긴 별도 클라이언트 하나와 추적되는 모사 팀원 3명으로 손전등 4개, 반복 총구 효과 4개, 문 6쌍의 개폐 24회, 스캔 홀로그램 4개와 AI가 켜진 몹 24마리를 실행했습니다. 카메라를 가리지 않도록 몹은 철창 뒤에서 경로 탐색을 합니다. 초기 준비 후 약 16초 동안 프레임 간격 3,616개와 서버 틱 처리 시간 320개를 측정했습니다.

환경: RX 6900 XT, 1280×720, Create 6.0.10 / Iris 1.8.14-beta.1 / Sodium 0.8.13 / Complementary Reimagined r5.9.3. 본인·팀원 그림자 설정 60Hz, 해상도 32입니다.

| 측정 대상 | 중앙값 | 95백분위 |
| --- | ---: | ---: |
| 클라이언트 프레임 간격 | 4.96ms | 7.19ms |
| 서버 틱 처리 | 4.16ms | 7.27ms |

네 개의 손전등 그림자 맵과 총구 광원 소스가 실제 생성된 것도 검사했습니다. 이는 현재 PC의 합성 부하 측정이며, 독립 클라이언트 4명의 접속·네트워크 지연·실제 총알 피해 연산을 재현한 검사는 아닙니다. 최적화 전후 FPS 비교도 아닙니다. 재현: `runClient -PloadSmoke -PopticalIris -PopticalCreate`, 결과는 `build/load-client-smoke/metrics.json`입니다. 검사 클래스와 실행 장치는 배포 JAR에서 제외합니다.

## 0.5.1

- 손전등 그림자를 계산할 때 좌표·법선·박스 임시 객체의 반복 생성을 줄였습니다. 이전 계산과 그림자 평면·경계 데이터가 정확히 같은지 여섯 방향과 여러 블록 형상으로 비교합니다. 밝기·거리·해상도·갱신 주기는 유지합니다.
- 스테이지 시작 때 타일 경계를 64블록 공간 단위로 분류합니다. 플레이어 위치와 방 판정은 주변 후보만 확인하며 청크를 읽거나 불러오지 않습니다. 경계의 포함·제외 규칙과 겹친 빈 공간의 기존 탐색 순서를 유지합니다.
- 비활성 일반 스캔은 플레이어 거리·벽 차폐 검사를 생략합니다. 잠긴 탈출 스캔의 화물 인계는 계속 확인하고, 인계로 목표가 완료되면 같은 틱에 스캔을 시작합니다. 활성 스캔의 진행·일시정지·네트워크 갱신 주기는 유지합니다.

개발 환경의 비교 측정에서 그림자 맵 한 번의 임시 메모리 할당은 585,676 → 531,248바이트로 약 9.3% 줄었습니다. 1,000개 타일·10,000회 위치 조회는 전체 순회 53.946ms → 공간 분류 조회 0.917ms였습니다. 이는 해당 연산의 비교 측정이며 전체 게임 FPS 향상 수치를 뜻하지 않습니다.

기본 GameTest 146개, 설치된 TaCZ 연동 6개와 CarryOn 화물 연동 1개를 통과했습니다. 숨긴 별도 클라이언트에서 기본 조명과 Create 6.0.10 / Iris 1.8.14-beta.1 / Sodium 0.8.13 / Complementary Reimagined r5.9.3 조합의 부분 블록·문 접촉 조명도 확인했습니다. 별도 스테이지에서 스캔 진행·인원 이탈 시 정지·다음 원 이동·목표 완료·문 잠금 해제·탈출 후 차원 복귀를 확인했습니다. 외부 모드 파일과 사용자 설정은 변경하지 않습니다.

## 0.3.32

문의 재질 형상은 개폐 위치나 문 종류가 바뀔 때 갱신하며 정지한 동안 재사용합니다. 문 양면의 조명 표본 위치는 문 위치·방향이 바뀔 때만 다시 만들고, 48개씩의 표본 버퍼를 재사용합니다. 실제 빛 읽기와 시간 보간은 매 렌더 프레임 유지합니다. 손전등의 갱신 주기·해상도·밝기는 변경하지 않았습니다.

이 변경은 문 하나당 매 프레임 생성하던 조명용 배열 두 개와 표본 위치 96개의 반복 생성을 없앱니다. 문짝이 정지하면 재질 타일 목록도 재생성하지 않습니다. 서버 충돌, 열림 속도, 문 연결과 조명 판정 규칙은 유지합니다.

게임 통합 검사 75개, 문 모델 검사, 실제 OpenGL 셰이더 검사를 통과했습니다. 이 수치는 게임 플레이 중 FPS 측정 결과가 아닙니다.
