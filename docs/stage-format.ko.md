# Erosion Sector 스테이지 파일 버전 2

스테이지 하나 = 편집 프로젝트 하나 = .esfile 파일 하나입니다. stage 폴더는 챕터와 무관하게 .esfile을 평평하게 모읍니다. 파일명은 표시용이며 챕터·미션 정보는 내부 설정이 기준입니다.

## 외부 타일

기존 tile/<타일셋>/<타일>.nbt 구조를 유지합니다. 타일은 압축 묶음으로 변환하지 않으며 스테이지 안에도 복사하지 않습니다. 타일 식별은 tile 폴더 기준 상대 경로 전체입니다. 연구소/복도.nbt와 공장/복도.nbt는 서로 다른 타일입니다. 절대 경로, 역슬래시, 빈 경로 조각, . 또는 .. 조각은 허용하지 않습니다. 경로 대소문자를 보존하며 일치하는 파일만 연결합니다. 이름이 같다는 이유로 다른 타일셋 파일을 선택하지 않습니다.

파일의 SHA-256은 수정 감지를 위한 값이며 이름을 대신하는 식별자가 아닙니다. 파일 내용이 바뀌면 자동 연결을 중단하고 편집기에서 명시적으로 설계도를 교체해야 합니다. 문 양면 접근 조건은 스테이지 설정에 보존합니다.

## 묶음 내부

.esfile은 표준 ZIP이며 아래 JSON 5개만 포함합니다. 타일 NBT·원본 base64·블록 점유 비트맵은 포함하지 않습니다.

- manifest.json: format=erosionsector-stage, version=2, tileRoot=tile, 좌표 단위와 타일 규칙. 게임 실행기는 아직 미구현이므로 status=draft, runtimeReady=false.
- stage.json: 스테이지 ID·이름·임무 설명, chapter의 ID·이름·설명, missionCode, 최소·최대 인원.
- tiles.json: 편집에 등록된 모든 타일의 ID·이름·분류·크기·문 연결구·양면별 조건. asset에는 reference(예: 연구소/복도.nbt), 이름·SHA-256·원본 통계만 저장합니다. 실제 NBT 없이 만든 설계용 타일은 asset=null입니다.
- layout.json: 타일 배치·회전·소속 방, 방·구역, 문 연결. blockPosition은 실제 정수 블록 좌표이며 Y는 8의 배수입니다.
- logic.json: 기믹 위치·설정과 이벤트 연결.

스테이지 외부에 stage.json을 별도로 두지 않습니다. .esproject를 따로 만들거나 관리하지 않습니다. 이전 파일 형식의 이전 처리는 제공하지 않습니다.

## 편집기 동작

.esfile만 열어도 배치·챕터·미션·기믹을 편집할 수 있습니다. 타일 NBT는 ‘타일 폴더 연결’에서 사용자가 선택한 tile 폴더에서 읽습니다. 원본 연결 전에는 누락 경고와 보수적인 저장 범위 충돌 검사를 사용하고, 연결 후 실제 비공기 블록으로 검사합니다. 파일·폴더를 웹 서버에 업로드하지 않습니다.

Chrome·Edge·Firefox에서 디렉터리 파일 입력으로 폴더를 읽습니다. 작업 폴더 직접 저장과 Minecraft 스테이지 실행기는 별도 구현 대상입니다. 현재 저장은 브라우저 다운로드입니다. 스테이지 파일을 공유할 때는 참조하는 외부 tile 폴더도 함께 전달해야 합니다.
