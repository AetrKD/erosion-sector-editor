# 구역 트리와 이벤트 블록

구역 트리는 숫자 구역 아래에 배치 인스턴스를 표시합니다. `101구역 → a구역 (복도 타일)`과 같은 구조이며 원본 타일과 배치 타일은 구분합니다. 같은 NBT를 여러 번 배치해도 각각 다른 하위 구역입니다. 복층 타일은 층별로 복제하지 않고 한 번만 표시합니다. 그 아래에는 해당 타일의 기믹이 표시됩니다.

숫자 구역의 내부 데이터는 기존 `rooms`, 시설 묶음은 `zones`입니다. 숫자 구역을 선택한 후 타일을 배치하면 a/b/c…z/aa 순으로 비어 있는 이름을 자동 부여합니다. 이름은 수정할 수 있고 같은 숫자 구역 안에서 중복할 수 없습니다. 삭제 후 남은 타일을 다시 번호 매기지 않습니다. 다른 구역으로 옮길 때는 새 구역의 비어 있는 이름을 사용합니다. 이벤트가 사용하는 `placement.id`는 변하지 않습니다.

## 조립

**이벤트 편집**을 열면 왼쪽에는 이벤트 목록, 가운데에는 검색 가능한 블록 목록과 조립 영역이 나옵니다. 지도용 선택·배치, 평면·입체 메뉴와 일반 속성 패널은 표시하지 않습니다. 실행 취소·다시 실행은 위쪽 공통 메뉴에서 사용합니다.

빈 이벤트를 만들거나 **구역 진입·소등과 경보 / 보안 문 시도·스캔 시작 / 스캔 완료·문 잠금 해제 / 키카드 획득·문 잠금 해제** 템플릿으로 시작하세요. 템플릿은 현재 프로젝트의 첫 대상을 기본으로 고르므로 구역·문·스캔 대상을 확인해야 합니다. 보안 문 시도로 시작할 스캔은 기믹 설정에서 처음에는 비활성화하고, 문 잠금 해제는 원하는 쪽 면을 지정하세요. 템플릿 추가가 기존 기믹 설정을 바꾸지는 않습니다.

왼쪽 검색으로 이벤트를 찾고, 블록 검색으로 분류와 관계없이 필요한 블록을 찾을 수 있습니다. 현재 추가 위치와 연결 가능한 종류가 블록 목록 위에 표시됩니다. **발생 조건 → 실행 동작** 순서로 구성하고, 분기 내부에서는 표시된 경로를 확인하세요. 이벤트 전체 복제는 대상 연결을 유지하면서 이벤트와 블록에 새 ID를 부여합니다.

개별 블록이나 전체 블록을 접어 흐름을 간략하게 볼 수 있습니다. 접기·펼치기와 블록 목록 표시 여부는 파일 내용을 바꾸지 않습니다. 좁은 화면에서는 추가 위치를 누르면 블록 목록이 열리고, 블록을 넣으면 다시 접혀 조립 영역을 넓게 보여줍니다.

1. 노란 시작 슬롯을 선택하고 발생 블록을 넣습니다. 기본은 스테이지 시작입니다.
2. 실행 순서 슬롯을 선택하고 실행·흐름 블록을 순서대로 넣습니다.
3. ‘만약’의 조건 슬롯에는 조건 블록을, 참/거짓 슬롯에는 실행·흐름 블록을 넣습니다.
4. ‘반복’의 내부 슬롯에는 반복할 동작을 넣습니다.
5. 블록을 팔레트에서 끌어 놓거나, 연결 위치를 선택하고 팔레트 블록을 누릅니다. 기존 블록의 제목을 드래그해 다른 목록으로 옮길 수 있고 ↑/↓로 순서를 바꿀 수도 있습니다. 복제·삭제와 실행 취소/다시 실행을 지원합니다.

발생을 조합할 때는 ‘모두 발생’ 또는 ‘하나 발생’ 안에 다른 발생 블록을 넣습니다. 조건도 모두/하나/반전으로 조합합니다. 여러 조건을 ‘만약’의 조건 슬롯에 직접 넣으면 모두 만족하는 조건입니다. 반전에는 조건 하나만 넣고, 여러 조건은 먼저 모두/하나로 묶습니다.

## 제공 블록

| 분류 | 블록 |
|---|---|
| 발생 | 스테이지 시작, 숫자 구역 진입, 하위 타일 진입, 터미널 명령어·화물 들기·키카드 획득·보안 문 시도·임무 목표 완료, 기믹 상호작용·목표 완료·경보 종료, 문 상태 변경, 이름 있는 신호 수신, 모두/하나 발생 |
| 조건 | 구역 내 플레이어, 기믹/임무 목표 완료, 알람 상태, 문 상태, 숫자 변수 비교, 모두/하나/반전 |
| 흐름 | 조건 분기, 횟수 반복, 초 단위 대기 |
| 실행 | 숫자 구역/개별 타일 조명 켜기·끄기·깜빡임, 문 개폐·면별 잠금/해제, 기믹 활성화·비활성화·완료, 임무 목표 완료, 경보·적 출현 시작, 안내 문구, 신호 발신, 변수 설정/더하기, 임무 성공·실패 |

경보와 적 출현은 해당 종류의 배치 기믹만 선택합니다. 문은 배치 ID와 연결구 ID로 구분하며, 잠금/잠금 해제 대상은 선택한 쪽 면입니다. 이름 변경 후에도 같은 개체를 가리킵니다. 대상이 삭제되면 다른 대상에 자동 연결하지 않고 검사 오류를 표시합니다. 사용하지 않는 이벤트의 오류는 경고로 표시합니다.

시설 터미널이 없는 프로젝트에서는 터미널 명령어 발생 블록을 새 블록 목록에서 숨깁니다. 기존 파일의 블록은 확인하고 수정할 수 있지만, 제거된 시설 터미널을 사용하는 이벤트는 다른 조건으로 바꿔야 합니다.

**흐름 보기**는 조건 분기를 포함한 읽기용 순서도입니다. 위쪽의 **모의 실행**에서는 가상 상태로 이벤트 연결을 확인할 수 있습니다. 실제 블록 충돌·몹·모드별 동작은 마인크래프트에서 확인해야 합니다.

## 파일 계약

`.esfile`은 기존과 같이 다섯 JSON만 포함합니다. `layout.json`의 배치에 `areaCode`를, `logic.json`에 `blockFormat: 1`과 `programs`를 저장합니다. NBT는 외부 `assets/tile/타일셋/타일.nbt` 경로를 그대로 참조합니다. 게임에서는 `es/` 아래에 둡니다.

```json
{
  "blockFormat": 1,
  "gimmicks": [],
  "links": [],
  "programs": [{
    "id": "event_power_loss",
    "name": "101구역 정전",
    "enabled": true,
    "once": true,
    "trigger": {"id": "block_enter", "type": "when.area", "args": {"roomId": "room_101"}},
    "actions": [
      {"id": "block_lights", "type": "do.areaLights", "args": {"roomId": "room_101", "mode": "off", "interval": 0.5}},
      {"id": "block_wait", "type": "flow.wait", "args": {"seconds": 3}},
      {"id": "block_alarm", "type": "do.alarm", "args": {"gimmickId": "alarm_101"}}
    ]
  }]
}
```

블록의 내부 슬롯은 `items`, `conditions`, `then`, `else`, `body` 배열입니다. 배열 순서가 실행 순서입니다. 모든 이벤트와 블록 ID는 파일 안에서 유일해야 합니다. 실행할 임의 JavaScript나 명령 코드를 저장하지 않고 정해진 종류와 속성만 사용합니다.

이벤트는 최대 300개, 전체 블록은 최대 5000개, 중첩은 최대 12단계입니다. 반복은 1~100회입니다. 블록 종류·속성·연결 위치·ID·중첩 한도는 불러오기와 수정 때 검사합니다. 연결 대상 누락, 빈 복합 블록, 빈 실행 목록과 신호 순환은 스테이지 검사에 표시합니다.

게임 실행기의 계약: `once`는 한 번 실행 여부입니다. `when.all`은 규칙이 활성화된 뒤 하위 발생이 모두 모이면 충족하고, 반복 실행 규칙은 다음 주기를 위해 수집 상태를 초기화합니다. 조건은 실행 진입 시 검사합니다. 이 실행 규약은 모드 0.4.0에 구현되어 있습니다.
