# ES 구조물 모델·텍스처 원칙 · 0.6.1

2026-10-20 사용자 결정: 현재 및 앞으로 추가하는 모든 ES 구조물은 ES 전용 모델과 직접 제작한 텍스처를 사용한다. 바닐라 블록을 설치해 외형을 조합하거나 바닐라 블록 모델·재질을 빌리는 방식은 사용하지 않는다.

## 현재 적용

기존 전용 거치대·미션 선택기/디스플레이·문의 형태는 유지한다. 바닐라 표면을 빌렸던 화물·보급함·문 프레임/구형 문짝·제어부·조명의 재질을 ES 전용 표면으로 교체했다. 화물은 보강 모서리·분리된 뚜껑·손잡이를 가진 전용 케이스, 일반/보안문 설치기는 전용 받침·금속 본체·상단 상태 표시가 있는 모델이다. 보급함은 전용 몸체·뚜껑·걸쇠·포인트 색을 쓴다. ID 카드와 ES 도구 아이콘도 직접 만든 그림으로 교체했다.

공통 금속·고무·상태 표시 재질을 여러 ES 구조물이 공유하는 것은 허용한다. 이를 통해 텍스처 중복과 메모리를 줄이며 바닐라 재질을 재사용하지 않는다. 기존 전용 문/거치대 아트와 색 조명은 보존한다. 바닐라 지형/건축 재료·외부 모드의 실제 장비는 이번 교체 대상이 아니다.

원본은 lobby-mod/tools/structure-assets.py의 직접 작성한 형상·색상·픽셀 패턴과 assets/erosionsector의 JSON/PNG다. 외부 게임 이미지를 입력으로 읽지 않는다. 15개32×32 전용 표면과4개32×32 전용 아이콘을 생성한다. 기존 소스 생성 도구의 바닐라 표면 참조도 교체했다. 빌드의 validateStructureAssets는 외부 모델/텍스처와 누락 PNG를 검사한다. 엔진의 minecraft:item/generated는 전용 아이콘을 그리는 일반 처리로만 허용한다.

## 렌더링·크기

대형 구조물의 기존5×1×3,4×1×1,8×1×4 및 컨테이너1/3/5칸 점유·충돌·상호작용은 유지한다. 큰 구조물은 하나의 전용 설계에서 정적 모델을 만들고 청크에 맞춰 나눈다. 점유 칸을 모두 없애는 것과 전용 모델을 사용하는 것은 다르다. 정적인 외형을 하나의 거대한 매 프레임 BER로 바꾸면 조명·가림·깜빡임·부하 문제가 생길 수 있으므로 그렇게 바꾸지 않는다. 문짝과 실제 동적 화면은 필요한 동적 렌더링만 유지하며 ES 전용 스프라이트를 사용한다.

JSON의 cuboid는 모델을 구성하는 면/형상이고 실제 바닐라 블록 설치가 아니다. 정적 면은 청크 메시로 굽는다. 전용 텍스처 교체만으로 모든 맵의 FPS 상승을 보장하지 않는다. 새 구조물은 중복 면·과도한 요소·투명 중첩·동적 렌더 횟수도 함께 검토한다.

## 웹 미리보기

공개 ES 리소스 묶음에도 같은 모델/텍스처를 반영한다. 이전 로컬 리소스 묶음을 이미 연결한 브라우저도 최신 ES 소유 리소스를 우선 합쳐 사용하므로 외부 모드 리소스를 다시 연결할 필요가 없다. 외부 Minecraft/Create/Copycats/Deco 원본은 계속 사용자의 브라우저에만 보관한다.

## 검사

전용 리소스/누락 검사와 기본 서버180개 통과. 보이는 기본 클라이언트에서 건축19/물품4 목록의 블록 아이템20개가 실제로 ES 스프라이트만 사용하는지,3D 모델·조명·GUI 변환을 확인했다. Create6.0.10/Copycats3.0.9/Deco2.1.3 및 기존 설치 조합·셰이더의 보이는 전용 클라이언트에서 화물/장치/보급함과1/3/5칸 상호작용을 확인했다. 웹 단위90개와 관련 브라우저8개도 통과했다. 상세 로그는 로컬 build/structure-*와 creative-model-smoke/,rework-client/native/에 있다.
