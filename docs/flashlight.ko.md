# 플레이어 공용 손전등 — Erosion Sector

총기·아이템·부착물 없이 **F**로 켜고 끕니다. E 공통 상호작용은 유지합니다. 설정 → 조작 → Erosion Sector에서 키를 바꿀 수 있습니다. F를 손전등으로 쓰는 동안 기본 보조 손 교체는 실행하지 않습니다. 메뉴·채팅에서는 조작하지 않습니다.

## 0.4.16 Create 사다리

Create 안산암·황동·구리 사다리에서 모델 전체가 충돌 판으로 처리되던 누락을 수정했습니다. 블록 밖으로 돌출된 고리도 실제 위치에서 검사하고, 위에 사다리가 있어 숨겨지는 고리는 그림자에서도 제외합니다. 원인과 검증 범위는 [모드 연동 안내](compatibility.ko.md)에 기록했습니다.

## 0.4.15 부분 블록 그림자

사다리의 충돌 판이 실제 표면을 가리거나, 엔드 막대의 그림자가 몸통보다 굵게 계산되는 문제를 수정했습니다. 일반 부분 블록은 베이크된 모델 면과 텍스처의 투명한 틈을 광학 형태에 반영합니다. 결과는 캐시해서 재사용하며 기존 손전등 밝기·거리·갱신 설정과 문 전용 처리는 유지합니다. 지원 범위와 복잡한 모델의 대체 동작은 [모드 연동 안내](compatibility.ko.md)에 정리했습니다.

설치된 Minecraft 모델을 사용한 실제 클라이언트에서 엔드 막대 6방향, 사다리 4방향의 불투명 부분·빈틈, 표면 자기 가림, 뒤쪽 벽 차단과 캐시 초기화를 검사했습니다. TaCZ와 함께 켠 기본 렌더러 및 Iris 1.8.14-beta.1·Sodium 0.8.13·Complementary Reimagined r5.9.3 조합에서 확인했습니다. 이 검증은 모든 모드·리소스팩·기울어진 모델의 정확도를 보장하지는 않습니다.

## 총구 점등과 공유

총구 조명도 같은 손전등 광원·원뿔·거리 감쇠·그림자 함수를 사용합니다. 총구에서는 사격할 때 짧은 주황빛으로 점등합니다. 0.3.32부터 거리는 손전등 기본 24블록, 총구 기본 32블록으로 독립 조절합니다. [총구 화염 안내](muzzle-flash.ko.md)를 참고하세요.

## 0.3.20 어두운 환경

실제 블록 광원·햇빛이 없는 월드 표면을 거의 검게 표시하고, 손전등·총구 조명은 그 위에 별도로 더합니다. 셰이더 환경에서도 적용합니다. 기존 월드 빛 데이터를 캐시하며 손전등 광선 검사를 추가하지 않습니다. [어두운 환경 안내](darkness.ko.md)를 참고하세요.

## 0.3.17 문 조명 수정

문짝은 실제 충돌면보다 1/16블록 안쪽에 표시됩니다. 이전 손전등은 바깥쪽 충돌면을 그림자로 사용해 문이 자기 자신을 가렸고, 중앙은 어둡고 테두리 일부만 밝게 보일 수 있었습니다. Erosion Sector 문에 한해 실제 표시 깊이의 문짝·고정 프레임·금속 테두리·버튼·보안 패널 모양을 광학 판정에 사용합니다. 플레이어 충돌, 문 크기, 멀티블록 구조, 개폐 시간은 유지합니다.

Iris 그림자 패스, 화면의 문짝, 손전등 차폐는 프레임마다 같은 보간 위치를 공유합니다. 시선이 정지해도 문이 움직이면 손전등 그림자를 다시 계산할 대상으로 표시합니다. CPU 예산과 광원별 갱신 간격 때문에 최종 그림자 맵이 모든 화면 프레임에 재계산되는 것은 아닙니다. 일반 블록과 서버의 몹 노출 판정은 기존 충돌 규칙을 유지합니다.

## 0.3.16 셰이더팩 연동 유지

Iris 셰이더팩을 켜거나 꺼도 Erosion Sector 자체 손전등 엔진을 사용합니다. 기존 LambDynamicLights 연동 클래스, 모드 의존성, 블록 밝기 격자 계산과 다운로드 준비 스크립트를 제거했습니다. 설치된 기존 엔진과 설정은 백업 후 제거합니다. 손전등 때문에 다른 동적 조명 모드를 설치할 필요가 없습니다.

Iris가 완성한 화면에 자체 조명을 합성하는 방식입니다. 셰이더팩 ZIP과 선택 설정은 바꾸지 않습니다. 팩 고유의 블룸·반사·안개 계산에 손전등 광원을 등록하는 방식은 아니므로, 이러한 효과가 손전등에 추가로 생성되지는 않습니다.

## 0.3.15 수정 유지

총기를 들 때 남은 충돌 로그는 Erosion Sector의 그림자 텍스처 업로드에서 발생한 네이티브 접근 오류를 가리켰습니다. 업로드가 다른 이미지 전송에서 남은 행 길이·시작 위치·바이트 순서·픽셀 버퍼 설정을 그대로 사용하던 누락을 수정했습니다. 업로드 전에는 자체 데이터에 맞춰 초기화하고 끝나면 이전 설정을 복원합니다. 화면 버퍼 생성에도 같은 처리를 적용하며, 화면 합성 후에는 사용한 텍스처 바인딩과 활성 단위도 복원합니다. 다른 모드를 제거하거나 그래픽 드라이버 설정을 바꾸지 않습니다.

그림자는 각 충돌면의 실제 사각 범위 안에서만 비교합니다. 범위를 벗어난 이웃 표본은 보간에서 제외하고 나머지 가중치를 다시 맞춰, 모서리의 잘못된 검은 영역과 연속된 벽 사이의 빛샘을 줄입니다. 표면 방향은 양쪽 두 번째 깊이 표본까지 비교해 다른 면을 가로질러 계산하지 않도록 개선했습니다.

## 자체 표면 조명

게임을 재시작한 뒤 F로 사용합니다. Iris에서 Complementary Reimagined 등 셰이더팩을 켜도 자체 엔진을 유지합니다. 셰이더팩 선택과 활성화는 기존 Iris 설정에서 직접 조작하세요.

- 월드 렌더링 후 장면의 색상과 깊이를 별도 버퍼로 복사합니다. 복사본을 읽으며 원본 화면에 출력하므로 읽기/쓰기 피드백을 피합니다. 바닐라 손·총기와 HUD는 이후 그려집니다. Iris는 손을 먼저 그리므로, 압축된 손 깊이 영역을 합성에서 제외합니다.
- 깊이와 실제 카메라 행렬로 표면 위치를 복원합니다. 양쪽 두 번째 깊이까지 이용한 평면 외삽 오차로 표면 방향을 계산해 모서리와 물체 가장자리의 잘못된 음영을 줄입니다.
- 기본 최대 24블록, 전체 약 56도 원뿔입니다. 중심은 밝고 가장자리는 부드럽게 약해집니다. 거리 감쇠는 `1-smoothstep(0,range,distance)`로 먼 끝에서 자연스럽게 0으로 수렴합니다. 표면 입사각을 반영하며 시선과 위치는 매 렌더 프레임 갱신합니다. 하늘에는 빛을 더하지 않습니다.
- 내 손전등을 우선하고, 카메라에서 48블록 안이며 시야에 영향을 줄 수 있는 가까운 팀원을 골라 **최대 4개**를 합산합니다. 팀원은 머리 시선을 보간합니다. 겹치는 빛은 점차 포화되도록 제한합니다.
- 광선 검사로 광원당 기본 **32×32 그림자 맵**을 만듭니다. Erosion Sector 문은 표시되는 광학 모양, 나머지 블록은 실제 충돌 모양을 사용합니다. 카메라에 보이지 않는 장애물도 차단하고, 액체는 차단하지 않습니다. 블록 밝기나 지형 메시를 갱신하지 않습니다.
- 그림자 맵에는 최초 충돌면의 법선·평면 위치·실제 충돌 모양의 면 범위를 저장합니다. 수신점이 같은 평면에 있으면 스스로 그림자를 만들지 않도록 비교하고, 면 범위 안에서 유효한 이웃 표본의 가시성을 보간합니다. 월드 좌표를 카메라 상대 좌표로 변환해 먼 좌표의 정밀도 저하를 줄입니다.

바닐라 화면에는 재질 원색을 별도로 저장한 버퍼가 없으므로, 이미 렌더링된 색상에서 표면 색을 근사합니다. 물리 기반 재질 조명이나 완전한 경로 추적이 아닙니다. 매우 어두운 화면의 색상 정보는 완전히 복원할 수 없습니다. 깊이를 기록하지 않는 투명 물체·입자, 손·총기의 별도 조명, 엔티티가 드리우는 그림자, 공기 중 빛줄기는 구현하지 않았습니다. 작은 장애물은 그림자 맵 해상도에 따라 빛샘이나 부드러운 경계가 생길 수 있습니다. 움직이는 문 그림자는 실제 클라이언트 충돌 모양의 갱신을 따릅니다.

## 성능과 설정

위치·시선과 화면 조명은 FPS에 맞춰 계산합니다. 무거운 그림자 맵 갱신은 내 손전등 최대 60Hz, 팀원 기본 최대 60Hz이며 실제 비용에 따라 느려질 수 있습니다. 움직이지 않으면 같은 월드 틱 안의 중복 광선 검사를 생략합니다. 월드 틱이 바뀌면 장애물 변경을 다시 확인합니다. 그림자 갱신 사이에도 최신 시선으로 빛 모양을 계산합니다.

프레임당 기본 2ms의 CPU 소프트 예산을 사용합니다. 개별 맵 하나의 계산을 중간에 끊지는 않으므로 엄격한 시간 상한은 아닙니다. 오래 기다린 팀원을 우선하는 순환 분배로 내 광원의 비용 때문에 팀원 조명이 계속 밀리지 않게 합니다. 월드가 바뀌거나 광원이 사라지면 관련 텍스처와 버퍼를 해제하고, 창 크기나 깊이 형식이 바뀌면 화면 버퍼를 다시 맞춥니다. 렌더링 예외가 나면 로그에 남기고 화면 조명을 중단합니다. 다른 엔진으로 전환하지 않습니다. 실제 게임의 FPS나 프레임 비용은 아직 측정하지 않았습니다.

`minecraft/config/erosionsector-client.toml`의 `[flashlight]`:

| 항목 | 기본 | 의미 |
|---|---:|---|
| `directLighting` | `true` | 셰이더팩 유무와 관계없이 자체 표면 조명 사용 |
| `strength` | `1.2` | 자체 화면 조명 세기, 0.25~3.0. 서버 판정에는 영향 없음 |
| `range` | `24` | 화면에서 비추는 거리, 6~32블록. 변경하면 그림자 맵도 다시 계산 |
| `shadowResolution` | `32` | 광원별 그림자 맵 너비, 16~64. 두 배로 올리면 광선 수는 네 배 |
| `maxHz` | `60` | 내 그림자 맵 갱신 상한. 문 움직임도 같은 갱신 예산으로 처리 |
| `teammateMaxHz` | `60` | 팀원 그림자 맵 갱신 상한 |
| `budgetMicros` | `2000` | 프레임당 CPU 소프트 예산. GPU 비용은 제외 |

## Iris 호환 범위

선택적인 Iris 연동은 API에서 팩 활성 상태와 그림자 렌더링 여부를 확인합니다. 활성 팩에서는 `CapturedRenderingState`의 gbuffer 카메라 행렬로 위치를 복원하고, Iris가 바닐라 메인 화면과 공유하는 깊이를 읽습니다. `AFTER_LEVEL` 시점은 Iris 최종 화면 합성 이후이며 색공간 변환 이전입니다. 일반 화면과 같은 원뿔·거리·충돌면 그림자 계산을 사용합니다.

Iris의 `HandRenderer.DEPTH`로 손 영역을 제외합니다. 텍스처 자체 설정을 덮어쓰는 하드웨어 샘플러는 합성 중에만 분리하고 이후 복원합니다. 텍스처 바인딩, 이미지 업로드 설정, 프레임버퍼, 깊이 쓰기, 블렌딩과 sRGB 상태도 복원합니다. 셰이더 전환 시 이전 좌표나 그래픽 상태를 강제로 유지하지 않습니다.

현재 설치된 Iris 1.8.14-beta.1 / Minecraft 1.21.1의 API·행렬 접근자·손 깊이 상수를 확인했습니다. 근거는 [Iris 최종 합성](https://github.com/IrisShaders/Iris/blob/1.21.1/common/src/main/java/net/irisshaders/iris/pipeline/FinalPassRenderer.java), [렌더링 순서](https://github.com/IrisShaders/Iris/blob/1.21.1/common/src/main/java/net/irisshaders/iris/mixin/MixinLevelRenderer.java), [손 처리](https://github.com/IrisShaders/Iris/blob/1.21.1/common/src/main/java/net/irisshaders/iris/pathways/HandRenderer.java)입니다. 지원되지 않는 Iris 내부 API에서는 안내를 표시합니다. 매우 가까운 표면은 손 깊이와 겹쳐 제외될 수 있습니다. 팩별 TAA 흔들림, 최종 화면 왜곡·피사계 심도, 비표준 깊이는 화면 가장자리나 투명 표면에 오차를 만들 수 있습니다. 모든 팩의 호환성이나 실제 게임 화면 검증을 보장하지 않습니다.

## 멀티플레이와 몹 판정

서버가 켜짐 상태를 확정해 전파합니다. 접속 중인 팀원에게 이미 켜진 상태도 전달합니다. 차원 이동, 사망, 관전자 전환, 접속 종료 시 해당 플레이어의 손전등을 끕니다. 화면의 블록이나 조명 블록, 몹 생성용 밝기와 저장 데이터는 바꾸지 않습니다. 배터리와 손전등 외형은 아직 없습니다.

`FlashlightService.strongestAt(ServerLevel, Vec3)`는 그 위치를 비추는 가장 강한 손전등의 UUID와 밝기를 반환합니다. `on(LivingEntity)`는 눈과 몸 중심을 검사합니다. 같은 차원의 켜진 플레이어만 검사하며 원뿔·거리 감쇠·실제 충돌 광선을 사용합니다. 서버는 클라이언트 그래픽이나 렌더링 조명 결과를 믿지 않습니다. 실제 반응형 몹·AI는 후속 작업입니다.

## 검증

서버 통합 검사 61개 중 손전등은 12개입니다. 방향·거리·벽 차단·패킷·상태 초기화와 함께 그림자 좌표의 수직/수평 투영, 수신면 자기 그림자 방지, 장애물 제거, 반블록 통과/차단, 충돌면 범위 밖의 잘못된 그림자 방지를 확인합니다. 문 검사는 양쪽 면과 네 방향의 일반/보안 문, 보간 위치의 통과 영역과 문짝 끝면, 실제 모델 파일과 광학 프레임의 일치를 포함합니다.

`tools/validate-flashlight-shader.ps1`은 Java 21과 PrismLauncher의 LWJGL 3.3.3으로 보이지 않는 OpenGL 창을 만듭니다. 실제 GLSL을 컴파일하고 두 화면 크기의 합성 장면에서 원뿔, 하늘 제외, 화면 밖 벽 차단, 수신면, 최신 시선, 손전등 4개 합산, 유한한 충돌면과 벽 이음새를 검사합니다. 모서리 양쪽 면은 128×96과 1920×1080에서 예상 밝기와 비교합니다. 실제 배포 코드의 업로드 보호 클래스를 컴파일해 잘못된 행 길이·건너뛰기·바이트 순서와 연결된 PBO가 있어도 픽셀을 정확히 올리고 이전 상태를 복원하는지 검사합니다. 게임을 실행하거나 사용자의 현재 월드를 조작하지 않습니다. 이 검사는 실제 Minecraft·Sodium·TaCZ 조합의 화면 품질과 FPS를 검증한 것은 아닙니다.

GPU 검사에는 gbuffer 카메라 회전, Iris식 손 깊이 제외, 하드웨어 샘플러의 분리·복원도 포함합니다. 문 표면보다 1/16블록 앞의 충돌면으로 어두운 중앙을 재현하고, 실제 표시 면에 맞추면 매끄러운 빛 분포가 복원되는지도 검사합니다. 이는 합성 장면 검사이며, 실제 Complementary 게임 화면을 실행해 확인한 것은 아닙니다. 개발 빌드에 외부 조명 API 다운로드나 추가 모드는 필요하지 않습니다.


0.3.23은 면 방향 계산을 화면 픽셀 면적과 무관하게 만들었습니다. 조명이 있는 바닥의 수평 밝기 경계를 Full HD·4K로 재현해 검사하며, 자세한 내용은 [어두운 환경 안내](darkness.ko.md)를 참고하세요.

0.3.24는 손전등 기본 세기를 2.4로 올려 먼 표면과 원뿔 가장자리의 가시성을 높였습니다. 광선 거리·폭·그림자 해상도와 갱신 예산은 유지합니다. 현재 인스턴스 설정도 함께 변경했습니다.

## 0.3.25 밝기·거리와 인게임 설정

모드 목록 → Erosion Sector → 설정 → 클라이언트에서 손전등, 총구 화염, 주변 어둠 항목을 엽니다. 정수 설정은 슬라이더로, 밝기 등 소수 설정은 숫자 입력으로 조절합니다. 완료로 상위 화면까지 돌아가 저장하면 다음 월드 프레임부터 반영됩니다. 모드 업데이트 직후에는 한 번 재시작해야 새 화면을 사용할 수 있습니다. 모든 항목은 클라이언트 시각 설정이며, 서버의 몹 노출 판정은 클라이언트 설정을 신뢰하지 않고 24블록의 같은 감쇠 곡선을 사용합니다.

밝은 표면 색을 일정 값부터 모두 1로 자르던 계산을 연속적인 압축 곡선으로 바꿨습니다. 손전등 1개·4개와 총구 점등 1개·4개가 철 재질의 서로 다른 무늬를 같은 흰색으로 만들지 않는지 GPU로 재현해 검사합니다. 실제 게임의 최종 재질은 기존처럼 원래 렌더링된 화면에서 근사하므로, 셰이더팩이 이미 지운 색상 정보까지 복원하지는 않습니다. 조명 없는 곳의 기본 밝기와 일반 조명 감쇠 기준 8은 유지합니다.

최대 거리를 늘려도 그림자 맵 광선 수와 CPU 예산은 유지합니다. 한 광선이 검사하는 거리는 길어져 비용이 늘 수 있으며 기존 적응형 갱신 제한이 적용됩니다. GPU 검사는 24블록 거리의 먼 벽 차단, 거리별 연속 감쇠, 24→6→32→24 설정 변경과 Full HD·4K 바닥의 밝기 경계 재발 여부를 포함합니다.
