# 로비 차원과 싱글플레이 · 0.5.3

메인 메뉴의 **싱글플레이**를 누르면 월드 선택·이름·시드·게임 모드 설정을 묻지 않고 새 ES 월드를 생성합니다. 날짜와 UUID를 포함한 새 저장 폴더를 사용하므로 누를 때마다 별개의 월드가 생깁니다. 기존 저장 폴더를 덮어쓰거나 지우지 않습니다. 생성 진행 화면은 표시됩니다.

싱글플레이 옆 **월드 목록**에서는 기존 월드를 불러오거나 일반 월드 설정 화면으로 건축용 월드를 만들 수 있습니다. 멀티플레이 버튼은 기존 서버 접속 흐름을 사용합니다.

자동 생성 월드의 기본값은 생존·보통 난이도·무작위 시드·하드코어 아님입니다. 생성할 때 `config/erosionsector-client.toml`의 `devmod=true`이면 명령어를 허용합니다. 생성 후 devmod 변경은 해당 월드의 명령어 허용 설정을 바꾸지 않습니다. 외부 모드와 Minecraft 파일은 수정하지 않고 NeoForge 화면 이벤트와 Minecraft 1.21.1의 `WorldOpenFlows.createFreshLevel`을 사용합니다.

## 로비와 최초 도착

기본 데이터팩이 `erosionsector:lobby`를 등록합니다. 개인 월드와 전용 서버 모두 같은 로비 차원을 생성하고, `erosionsector:mission`은 별도로 유지합니다. 전용 서버에는 싱글플레이 메뉴 코드를 로드하지 않습니다.

건축 설계도가 아직 없으므로 로비에 17×17블록의 임시 발판을 만듭니다. 바닥은 Y=63, 최초 도착은 X=0.5 / Y=64 / Z=0.5이며 바닥 조명과 가장자리 2블록 높이 유리 난간을 둡니다. 이 임시 발판에 장비 선택기나 임무 선택 기능을 자동 배치하지는 않습니다.

발판 생성 여부는 로비 차원의 SavedData에 저장합니다. 서버 재시작·재접속 때 발판을 다시 만들지 않으므로 사용자가 건축한 내용은 유지됩니다. 최초 접속 플레이어는 로비로 이동하고 강제 부활 위치도 로비로 지정합니다. 재접속은 기존 저장 위치를 유지합니다. ES를 새로 설치한 기존 월드에서는 플레이어별 첫 ES 접속 때 로비로 이동합니다.

임무 밖에서 사망하면 로비 도착 위치에서 부활합니다. 진행 중인 임무의 대원은 기존 StageRuntime의 사망·관전 처리를 유지합니다. 임무 완료·실패 후 복귀는 출발 전 차원·좌표를 사용하는 기존 규칙을 유지합니다. 최초 도착 표시는 부활 플레이어에도 복사합니다.

로비 건축물 NBT 불러오기, 사용자 지정 로비 도착 좌표, 실제 .esfile 임무 목록과 출발 버튼 연결은 별도 작업입니다.

## 검증

기본 서버 검사 148개를 통과했습니다. 실제 로비 데이터 리소스를 읽어 최초 접속·강제 부활·재접속 위치 유지·발판 재생성 방지·부활 데이터 복사를 확인합니다. 임무 생명주기 검사에는 사망한 탐사대원의 관전 상태를 로비 부활 처리가 가로채지 않는 검사도 포함합니다.

`gradlew.bat runClient -PlobbySmoke --offline`은 사용자 저장 폴더와 분리된 개발 환경에서 표시되는 게임 창으로 실행합니다. 실제 메인 메뉴 클릭, 두 차원의 존재, 로비 도착, 실제 사망·부활, 저장 후 재접속 시 건축물·위치 유지, 두 번째 클릭의 독립된 월드 생성을 확인합니다. 검사 클래스는 배포 JAR에서 제외합니다.
