# 타일 반쪽 문 — Erosion Sector 0.3.35

## 0.4.25 문 앞 엔티티 밝기

닫힌 문의 실제 두께는 각 블록 칸의 절반이지만, 기본 블록 광원 데이터는 차폐를 위해 그 칸 전체에서 0이 될 수 있습니다. 몹·플레이어·아이템이 문에 바짝 붙으면 기본 엔티티 렌더러가 비어 있는 반쪽 공간에서도 이 0을 읽어 지나치게 어둡게 표시했습니다. ES 조명 효과를 꺼도 발생하는 문제입니다.

ES 문 칸의 빈 공간에 놓인 엔티티 밝기 좌표만 해당 반쪽 문의 바깥쪽, 즉 엔티티가 서 있는 방으로 옮깁니다. 실제 충돌 형상 안에 들어간 좌표, 일반 블록과 빛이 통과하는 문은 기본 처리를 유지합니다. 주변의 가장 밝은 칸을 고르거나 반대편 방의 빛을 가져오지 않습니다. 문의 광원 차단량·충돌·개폐 동작과 기존 엔티티 렌더러의 발광·불붙음 처리는 변경하지 않습니다.

기본 클라이언트와 TaCZ·Create·Iris·Sodium·Complementary Reimagined r5.9.3에서 ES 효과 켜짐·꺼짐을 모두 검사했습니다. 재현 장면의 몹은 0→9, 아이템은 0→8로 보정됐으며 어두운 반대편은 0을 유지했습니다. 기본 GameTest 136개도 통과했습니다.

크리에이티브 Erosion Sector 탭의 **일반 문 자동 설치 블록**과 **보안 문 자동 설치 블록**을 사용합니다. 출입구 안쪽 바닥에 설치하면 자기 타일의 두께 절반만 구성합니다.

| 종류 | 전체 크기 | 개방 동작 | 하단 턱 | 상단 프레임 |
|---|---|---|---|---|
| 일반 소형 | 4×4 | 한 문짝이 위로 이동 | 1/8 | 3/8 |
| 일반 중형 | 6×4 | 한 문짝이 위로 이동 | 1/8 | 3/8 |
| 일반 대형 | 10×6 | 중앙에서 위·아래 두 조각으로 분리 | 1/4 | 1/4 |
| 보안 소형 | 4×4 | 중앙에서 좌·우로 분리 | 1/8 | 1/8 |
| 보안 중형 | 6×4 | 중앙에서 좌·우로 분리 | 1/8 | 1/8 |
| 보안 대형 | 10×6 | Y자 경계의 세 조각이 각각 바깥으로 이동 | 1/4 | 1/4 |

전체 크기는 프레임 포함입니다. 양옆 프레임은 모두 1/4블록입니다. 대형 보안 문의 분할선은 정면 기준 위쪽 0도, 시계 방향 120도와 240도이며, 각 조각은 그 사이 방향으로 이동합니다. 실제 문짝·텍스처가 함께 움직이고 프레임 안에서 잘려 수납됩니다. 위층·옆방으로 블록을 이동시키지 않습니다.

## 설치와 설계도

1. 양옆 벽과 천장·바닥의 안쪽 사이를 4×4, 6×4 또는 10×6으로 만듭니다. 바닥과 벽·천장 경계에는 안쪽 면이 막힌 블록을 사용합니다.
2. 출입구 안쪽 바닥의 윗면에 설치 블록 하나를 놓습니다. 어느 가로 위치에서 설치해도 자기 쪽 한 줄만 구성합니다. 자기 쪽 공간에 다른 블록·액체가 있으면 아이템을 소비하지 않습니다.
3. 반쪽은 **조립 중** 상태로 닫혀 있습니다. 반대편에 블록을 생성하지 않고, 혼자서 삭제되거나 작동하지 않습니다. Shift+E로 구동부 화면을 열면 조립 중 상태를 확인할 수 있습니다.
4. 맞은편 타일에도 같은 크기·종류의 문을 마주 보게 설치합니다. 두 반쪽의 위치·높이·방향이 맞으면 문 하나가 됩니다. 총 두께는 1블록이며 각 타일은 반 블록씩 사용합니다.
5. 타일 설계도에는 자기 영역의 **구동부와 본체 전체**를 포함합니다. 상대 타일이나 상대 제어부 주소는 저장하지 않습니다. 높이는 8의 배수로 내보냅니다.

새 위치로 복사하거나 수평 회전·반전해도 로컬 프레임과 구동부에서 연결을 다시 찾습니다. 나중에 배치되는 반대편을 기다릴 수 있으며 짝이 없는 반쪽은 삭제하지 않습니다. 스테이지 로더는 아직 별도 구현 대상입니다. 새 반쪽 문 블록은 tile_door_part / tile_door_drive / tile_security_door_drive이고, 이전 수동 천장 구동부와 섞어 연결하지 않습니다. 기존 완성 문은 자동 변환하지 않으므로 새 방식은 자동 설치 블록으로 다시 만드세요.

## 양면 조건과 조작

일반 문은 양면에서 정면 기준 오른쪽 버튼을 조준하고 E로 조작합니다. 보안 문의 패널은 소형·중형은 각 면에서 바라본 오른쪽, 대형은 하단 문짝 중앙에 있습니다. 패널에서 E를 1초 유지하여 개방하며, 폐쇄는 터미널 CLOSE나 기믹 신호로만 합니다. 자동 닫힘은 없습니다.

접근 조건·알람·인증 상태는 각 면이 소유합니다. 예를 들어 바깥쪽은 ALARM, 안쪽은 HOLD로 설정하면 바깥쪽은 알람 완료 후 상호작용해야 하고 안쪽은 조건 없이 상호작용할 수 있습니다. 안쪽에서 열어도 바깥쪽 인증 상태는 바뀌지 않습니다. 실제 문짝과 열린 통로는 하나이므로 어느 쪽에서 열든 양쪽에서 통과할 수 있습니다.

기존 /erosionsector door set, alarm_start, alarm_complete, authorize, close 명령은 지정한 좌표가 속한 면을 대상으로 합니다. 웹 편집기도 각 연결구에 해당 면의 조건을 보존합니다. 게임 스테이지 파일 실행과 자동 이벤트 연결은 아직 미연결입니다.

부품 하나를 부수면 연결된 문 전체가 철거되며, 미연결 상태에서는 자기 반쪽만 철거됩니다. 파괴 조건을 따르고, 별도 문이나 주변 벽·다른 블록을 삭제하지 않습니다. 닫히는 문은 엔티티를 가까운 안전한 쪽으로 밀고, 블록 장애물이나 안전한 출구가 없으면 다시 열립니다.

## 조명과 검사

기존 손전등·총구 화염 기본값을 유지합니다. 손전등 차폐는 표시하는 보간 문짝과 같은 다각형에서 계산합니다. 충돌/광학 형태의 경사면은 최대 1/16블록 높이의 띠로 근사하고 설치 광원은 기존 블록 광원 전파를 사용합니다. 제거했던 화면 합성형 문 연속 그림자는 사용하지 않습니다.

통합 검사는 여섯 동작의 범위·프레임·재질 좌표, 세 크기와 네 방향의 실제 설치, 반쪽의 지연 연결, 다른 면의 조건, 1초 상호작용, 모든 수평 회전·반전 후 연결, 일괄 철거와 장애물 복구를 포함합니다. 실제 게임의 외형과 셰이더팩별 화면은 추가 확인이 필요합니다.

### 0.3.36 설치 시 충돌 수정

Sodium의 병렬 청크 메시 작업이 문 충돌 형태를 조회할 때 0.3.35의 공유 HashMap.computeIfAbsent에서 ConcurrentModificationException이 발생했습니다. 각 문 자세에 별도의 ConcurrentHashMap을 가진 스냅샷을 사용하고, 자세 변경 때 기존 맵을 지우는 대신 새 스냅샷으로 교체합니다. 이전 작업이 늦게 완료되어도 새 자세 캐시에 이전 충돌 형태를 쓰지 못합니다. 형상 계산 중에는 월드에 다시 접근하지 않도록 필요한 기하 정보를 먼저 고정합니다.

회귀 검사는 여섯 종류 문을 8개 작업에서 동시에 조회하고, 열린/닫힌 자세 전환·캐시 무효화 중에도 각 요청에 올바른 형태가 유지되는지 확인합니다. 문 규격·설치 방식·조명 기본값은 변경하지 않습니다.

### 0.3.37 문짝 끝면 조명

끝면을 재질용 구간으로 나누더라도 밝기는 각 꼭짓점에서 보간된 앞·뒤 면의 광량을 사용합니다. 구간 중앙의 단일 밝기와 양면 중 최댓값을 전체 끝면에 적용하던 처리를 제거해 구간 경계와 어두운 면의 과도한 밝기를 줄입니다. 끝면 음영도 실제 법선 방향을 반영하고, 면 방향을 뒤집을 때 위치·UV·광량이 같은 꼭짓점을 따라갑니다. 월드 광원 전파나 바닥·벽에 드리우는 그림자 엔진은 변경하지 않습니다.

### 0.3.38 전용 픽셀 아트와 조작함

바닐라 철 블록·회색 콘크리트를 조합하던 새 문에 일반/보안 × 세 크기의 전용 PNG, 프레임 재질, 조작함 JSON 모델을 적용합니다. 표면 질감과 노이즈 없이 고정 16색 팔레트를 사용하며, 문짝 그림은 통로 전체를 기준으로 매핑해 실제 분할·이동과 함께 움직입니다. 불투명 밉맵 렌더링을 사용합니다.

기존 버튼은 프레임과 앞면이 같은 평면에 있어 깜빡일 수 있었습니다. 새 조작함의 누르는 면은 프레임에서 돌출되어 있고, 모델 JSON·선택·E 판정·손전등 차폐의 위치를 맞췄습니다. 모델과 판정은 자기 블록을 벗어나지 않습니다. 문짝 크기·개폐 방식·조명 설정은 바꾸지 않습니다. 참고 이미지·Blockbench 파일과 생성 프롬프트는 `assets-source/doors/README.ko.md`에 정리했습니다.

### 0.3.39 크기·종류별 외형과 실제 크기 기준 해상도

여섯 문에 각각 다른 원본 그림을 사용합니다. 일반 소형은 설비 해치, 중형은 셔터, 대형은 수평 분할 방호문이며, 보안 소형은 금고판, 중형은 녹색 차폐문, 대형은 Y자 3분할 장갑판입니다. 큰 사각 패널과 단순한 픽셀 표시를 사용하고 문별 팔레트를 제한합니다. 프레임·조작함과 여섯 개폐 동작은 유지합니다.

전체 PNG는 프레임 포함 크기에 맞춰 64×64 / 96×64 / 160×96픽셀입니다. 문짝의 그림은 프레임 안쪽에 배치하고 UV는 전체 문 기준으로 계산하여, 실제로 블록당 16픽셀의 크기를 유지합니다. 움직이는 패널에서 UV 이동을 빼므로 그림은 문짝과 함께 움직입니다. 프레임을 뺀 문짝에 전체 그림을 늘여 붙이지 않습니다. Blockbench 참고 모델과 미리보기에도 같은 좌표를 적용합니다. 설치·충돌·차폐·광원 설정은 변경하지 않습니다.

### 0.3.40 보안 문 조작 패널 위치

소형 패널 중심은 문의 중앙에서 정면 기준 오른쪽 7/8블록, 중형은 오른쪽 1과 1/4블록입니다. 반대편에서도 그 면을 바라본 오른쪽에 배치하고, 패널 안의 아이콘 방향도 맞춥니다. 대형은 가로 중앙을 유지한 채 1.5블록 아래로 내려서, 문 아래에서 1.5블록 높이의 하단 문짝에 배치합니다.

화면 전체가 소형·중형의 세로 분할선과 대형의 Y자 분할선을 피하며 프레임 안쪽에 들어갑니다. 패널 크기는 가로 1.5 × 세로 7/8블록으로 유지합니다. 표시·선택 윤곽·E 안내·서버의 상호작용·손전등 차폐가 같은 위치 계산을 공유합니다. 이전 중앙 지점을 겨냥해도 상호작용을 시작하지 않습니다. 1초 유지, 해제 조건, 외부 신호 폐쇄와 개폐 동작은 유지합니다. 기존 문을 다시 설치할 필요는 없습니다.

회귀 검사는 세 크기 × 네 방향 × 양면에서 실제 선택 광선이 패널에 닿는지, 화면 전체가 물리 문짝 하나 안에 있는지, 여러 블록에 걸친 화면 조각이 빠짐없이 같은 크기로 구성되는지 확인합니다. 전체 통합 검사 93개를 통과했습니다. 실제 게임의 화면과 셰이더별 외형은 별도 확인이 필요합니다.
