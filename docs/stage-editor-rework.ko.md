# 스테이지 편집기 개편 · 모드 0.6.0

## 사용하는 순서

1. **타일 배치**에서 타일 폴더를 연결하고 카드를 지도로 드래그한다. 배치된 타일도 드래그로 옮기며 R로 회전하고 Delete로 지운다. 진입/탈출 타일은 오른쪽 속성에서 지정한다.
2. **자원 및 목표 배치**에서 종류·총 사용량·묶음 수·타일/구역을 정한다. 고정 스캔·경보·터미널·컨테이너·상호작용 장치는 이 화면의 ‘고정 요소’에서 만들고 위치·설정을 편집한다.
3. **변수**, **적**, **목표**에서 이름 있는 항목을 등록하고 **이벤트 관리**에서 연결한다. 목표에는 메인 묶음 하나와 이름이 다른 여러 서브 묶음이 있다.
4. 저장한 `.esfile`과 원본 NBT를 게임의 같은 작업 폴더에 둔다. 새 기능이 있는 파일은 형식 버전3이며 모드0.6.0이 필요하다. 기존 버전2 파일도 읽는다. ZIP 안의 JSON5개와 외부 NBT 상대 경로/해시 계약은 유지한다.

체크리스트는 미연결 문 없음·진입점 존재·탈출 방법 존재의 세 가지 자동 상태다. 탈출 방식은 ‘탈출 자체가 목표’와 ‘메인 목표 완료 후 탈출’을 구분한다. 후자는 탈출구 활성화 또는 즉시 성공을 선택한다. 체크리스트 통과는 모든 이벤트 경로의 성공을 증명하는 뜻이 아니다.

## 블록 미리보기와 리소스

타일 배치 안의 미리보기를 켜면 왼쪽 절반에 선택 타일의 모델·텍스처·스캔 표시를 그린다. 일반 JSON blockstate/variants/multipart/부모·텍스처·회전과 정지 상태를 사용한다. 지원 대상 리소스 버전은 Minecraft1.21.1, Create6.0.10, Copycats+3.0.9, Create Deco2.1.3, ES0.6.0이다.

원본 모드 JAR는 웹으로 올리지 않는다. Create6.0.10의 JAR 내 LICENSE.md_create-1.21.1은 assets를 All Rights Reserved로 명시하며 Copycats+ 저장소 LICENSE도 재배포 허용문이 아니다. 공개 배포에는 ES 소유 리소스와 규칙 메타데이터만 포함한다. 다른 원본 블록 리소스는 사용자의 로컬 `.esresources` 묶음을 **블록 리소스 연결**로 한 번 읽고 해당 브라우저 IndexedDB에 보관한다. 파일과 타일은 서버에 전송하지 않는다. 다른 브라우저/사이트 주소에서는 다시 연결한다.

개발 도구 `tools/build-preview-resources.py`는 설치된 정확한 JAR와 ES 작업 리소스를 읽는다. 기본 실행은 Git에서 제외된 artifacts/local-block-resources와 artifacts/block-resources.esresources만 만든다. `--public`은 ES 리소스만 dist에 만든다. 모드 전체 JAR나 타일별 모델 추출기는 필요하지 않으며 재질 조합을 전수 저장하지 않는다. 도구 실행에는 Python과 Pillow가 필요하다.

Copycat의 Material/material 및 material_data의 각 부분 재질을 읽는다. 금 계단, 축 방향·위/아래가 다른 재질의 반블록, 여러 면의 보드와 바이트, 기본 블록·패널·일반 계단 등의 고정 어댑터가 있다. 타일 내부 이웃과 Create/Deco CT 테이블을 사용하며 타일 바깥은 경계로 처리한다. 완전한 임의 Java 모델 실행기는 아니다. 경사/수직 계단·톱니·파이프 등 일부 동적 Copycat 형태는 미지원 표시와 ID를 확인해야 한다. 복잡한 다중 부분의 접촉·모든 모드별 CT 특수 연결도 완전 재현을 보장하지 않는다. 게임 조명·셰이더·개폐 애니메이션은 범위 밖이다.

리소스는 미리보기를 열 때 로딩하고 모델/텍스처를 재사용한다. NBT 파싱 결과8개와 표시 높이·오버레이별 메시 최대48MiB를 캐시한다. 리소스 묶음을 바꾸면 관련 그래픽 캐시를 비운다. 누락을 대체 무늬로 알리고 NBT를 바꾸지 않는다.

## 보급품과 컨테이너

- 탄약/체력 팩은 겹쳐지지 않는다. 한 팩 최대5회, 잔량1회=20%, 5회=100%다. 성공하면 한 회분을 쓰고 마지막 사용으로 소진된다. 기존 보급 효과의 수치와 설정은 유지한다.
- **좌클릭 1초 유지**: 자신에게 사용. **우클릭 1초 유지**: 조준한 다른 플레이어에게 사용. 상대는 시야2블록 안에 있어야 한다. 상대가 없으면 자기 사용으로 대체하지 않는다. 대상·시야/범위·슬롯·아이템·사용 상태를 서버가 재검사하며 취소 시 소모하지 않는다. 연속 중복 사용은 키를 떼야 다시 시작된다.
- 새 컨테이너는 supply_small(한 블록 내 공구상자 형태,1칸), supply_medium(1×1×2,3칸), supply_large(너비2×깊이1×높이2,5칸)다. 어떤 부분을 열어도 같은 수납을 사용하고 일부를 부수면 구조 전체를 정리한다. 서바이벌 UI에는 기존18칸 인벤토리만 보인다.
- 구형 supply_container의9칸과 기존 월드 물품은 유지한다. 기존 겹친 팩은 서바이벌 인벤토리 정리 때 개별 팩으로 나누며 빈칸이 부족한 물품은 복구 보관한다. 저장된 팩 하나는 새 최대5회분 팩으로 취급한다.

## 슬롯 배정과 실행

NBT 컨테이너 위치와 액자 위치를 각각 후보 슬롯으로 추출한다. 새 다중 블록 컨테이너는 기준 블록 하나만 센다. 수납 용량1/3/5와 구조물 개수는 다르다. 액자는 위치·방향을 읽고 오브젝트/키카드/화물 자리로 대체한다.

총 사용량을 묶음 수에 나눈 뒤 각 팩 최대5회분으로 나눈다. 총13회분을2묶음으로 만들면 [5+2], [5+1]이고 각각 수납2칸이 필요하다. 오브젝트는 총 개수와 묶음 수를 같게 하여 슬롯당1개로 둔다. 타일 규칙부터 배정하고 구역 규칙은 남는 수납을 쓴다. 후보를 한 번 섞어 확정하고, 부족하면 일부를 버리는 대신 임무 준비 오류를 낸다.

자원 규칙이 있는 스테이지는 실행용 복사 맵의 후보 컨테이너 원래 내용을 비우고 배정한다. 선택하지 않은 컨테이너와 자리 표시 액자를 제거한다. 규칙이 없는 구형 임무는 원래 내용을 유지한다. 원본 NBT는 수정하지 않는다. NeoForge IItemHandlerModifiable을 통한 공개 인벤토리 접근도 지원하며 실제 용량을 채우기 전에 확인한다. 임의 모드의 특수 수납은 모두 호환된다고 가정하지 않는다.

여러 진입점은 참가자와 진입점 순서를 섞어 순환 배정한다. 인원 차이는 최대1명이고 각 타일 안에 서로 겹치지 않는 안전한 발판을 찾는다. 공간이 부족하면 준비 오류가 난다.

## 이벤트와 목표 계약

팔레트는 요구한29종(발생9/조건7/흐름4/실행9)이며 구형 파일의 다른 블록은 불러오기와 실행을 위해 유지한다. 제목 클릭/Enter로 블록을 접는다. 템플릿·예시·흐름 보기·목록 접기 버튼은 제공하지 않는다.

stage.json 확장: variables[{id,name,initial}], enemyGroups[{id,name,scope,targetId,entity,count,waves,interval,minDistance,sleeping,enabled}], resourceRules[{id,name,kind,scope,targetId,total,bundles,objectKey}], objectiveGroups[{id,name,kind}], successMode(extraction/direct). objectives는 groupId,amount,enabled를 추가한다. 메인 묶음 목표는 필수이고 서브는 선택이다.

변수는 세션마다 초기화하고 비교/변경의 오른쪽 valueVariable을 지정하면 숫자 value 대신 해당 변수 값을 쓴다. until 반복은 조건이 충족될 때 종료하며 서버 틱에 나눠 실행한다. 적 그룹 waves=0은 무한이며 정지/임무 종료 시 예약을 멈춘다. 생성 공간·거리가 맞지 않으면 빈 웨이브를 완료로 세지 않고 재시도한다. 음악은 사운드 리소스 ID/음량/재생·정지이며 임무 종료 시 정리한다.

목표 진행은 수량·완료 이벤트로 연결한다. 생존 목표는 활성 시간만 누적하고 길 정리는 해당 적 그룹의 생성 완료와 잔존 몹0을 기다린다. 스캔 목표 활성·비활성은 연결된 스캔 시작·정지와 함께 처리한다. 이벤트의 완료 처리는 비활성 목표도 명시적으로 완료한다.

## 검증 기록

기본 서버 GameTest180개, 웹 단위 검사90개, 새 UI 및 기존 스캔/이벤트/성능 브라우저17개 통과. 실제 웹 생성v3 파일→게임 로딩→3개 중1개 컨테이너에 잔량40% 팩→나머지2개 제거→원본 NBT 불변,4명/2진입점 배분을 검사했다. 보이는 전용 개발 클라이언트의 기본/설치 모드 조합에서1/3/5칸 화면·보급품 좌클릭·진행 HUD·18칸 인벤토리를 확인했다. Copycats 실제 BE가 저장한 material_data의 금/다이아 반블록을 웹에서 렌더링하고 새로고침 후 로컬 리소스 보존을 확인했다.

로그는 로컬 lobby-mod/build/rework-*이고 공개 문서에 개인 파일·자격 증명을 넣지 않는다. 구형 메뉴·클릭 배치·템플릿 버튼을 전제로 한 일부 기존 브라우저 시나리오는 새 UI 계약과 다르며 전체 구형 브라우저 모음을 통과했다고 주장하지 않는다. 개인 클리어 기록 클라우드 동기화 비활성 정책은 유지한다.
