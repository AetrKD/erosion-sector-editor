# Erosion Sector Editor

배포: https://erosion-sector-editor.vercel.app/ · 소스: https://github.com/AetrKD/erosion-sector-editor

Create 설계도로 저장한 타일, 방·구역과 기믹을 조합하는 웹 앱입니다. 설치 없이 배포 주소에서 사용하거나, 이 폴더의 정적 앱을 로컬로 실행할 수 있습니다.

## 지금 사용할 수 있는 기능

- 가로·깊이는 양의 정수, 높이는 8블록의 배수인 Create/바닐라 구조물 `.nbt` 가져오기. gzip과 비압축 구조물을 읽습니다.
- 외부 tile 폴더의 상대 경로로 설계도 연결, SHA-256 변경 확인, 블록·팔레트·문 마커 개수와 포함된 블록 네임스페이스 표시.
- 타일 라이브러리, 건축물 없이 먼저 배치할 수 있는 설계용 타일 생성, 같은 크기의 설계도 연결/교체.
- 층별 평면도와 전체 타일 점유 공간의 입체 보기. 드래그로 시점 방향·높이를 바꾸거나 회전 버튼으로 45도씩 돌릴 수 있습니다. 입체 보기는 건축물의 블록 외형을 렌더링하지 않습니다.
- 입체 타일은 불투명하게 표시하고 WebGL 깊이 버퍼로 앞뒤를 판정합니다. 가려진 면과 라벨을 숨기고 클릭한 위치에서 가장 가까운 타일을 선택합니다. WebGL을 사용할 수 없는 환경에서는 안내와 함께 간이 입체 보기를 제공합니다.
- 격자 클릭 배치, 선택·드래그 이동, 좌표 입력, 수평 90도 회전, 복제와 삭제.
- 설계도의 실제 블록 점유를 이용한 3차원 겹침 검사. 저장 범위가 겹쳐도 공기끼리 또는 공기와 블록만 겹치면 허용하며, 실제 블록이 겹치면 해당 좌표를 표시합니다. 설계도가 없는 설계용 타일은 저장 범위 전체를 예약합니다.
- 복층 타일은 여러 높이 화면에 나타나는 하나의 인스턴스입니다. 상층 문 옆에 단층 타일을 높여 배치할 수 있습니다.
- 동서남북 연결구의 위치·실제 높이·폭·높이 크기를 비교해 연결 판정.
- 구역과 방 생성, 방별 번호·이름·고유 ID·색상, 타일의 소속 방 지정.
- 시작점, 목표 단말기, 경보, 적 출현, 보급, 탈출, 진입 트리거의 위치와 설정 편집.
- 기믹 사이 발생 이벤트와 대상 동작 연결.
- 실행 취소/다시 실행, 브라우저 IndexedDB 자동 저장, 단일 .esfile 스테이지 저장/복원.
- 기본 예시 `A1 · 잠든 관측소`: 진입실 → 복층 홀 → 연구실 방어전 / 상층 제어실 → 진입실 탈출.

## 사용 순서

1. Create에서 타일 건축물을 구조물 `.nbt`로 저장합니다. 가로·깊이는 자유롭게 지정하고 높이는 8의 배수로 저장하세요. 타일 외곽에 Erosion Sector 문이 최소 하나 있어야 가져올 수 있습니다.
2. ‘Create 설계도 가져오기’로 등록합니다. 실제 건축물 없이 작업하려면 기본 설계용 타일이나 ‘설계용 타일 만들기’를 사용합니다.
3. 타일 원본 속성에서 문 연결구를 설정합니다. 문 이름, 방향, 위치, 폭·높이와 연결 필수 여부를 지정합니다.
4. 방·구역 탭에서 방을 고르고, 타일을 배치합니다. 배치한 타일의 소속 방은 속성에서도 변경할 수 있습니다.
5. 층 탭을 바꾸어 상층 문과 복층 공간을 확인합니다. 타일 속성의 ‘층 높이’는 격자 Y이며 1칸이 8블록입니다.
6. 기믹을 골라 타일 내부에 배치하고, 속성에서 수량·시간·좌표 및 이벤트 연결을 설정합니다.
7. 하단 검사 버튼으로 공간·연결구·참조를 확인합니다.
8. ‘스테이지 설정’에서 챕터·미션 설명을 지정한 뒤 ‘스테이지 저장’으로 .esfile을 저장합니다. 편집과 실행에 같은 스테이지 파일을 사용합니다. 타일 NBT는 묶음에 포함하지 않습니다.

단축키: V 선택, B 타일 배치, R 회전, D 복제 배치, Del 삭제, Ctrl+Z/Y 실행 취소/다시 실행, Ctrl+S 프로젝트 파일 저장. 휠 확대, Space+드래그 또는 휠 버튼 드래그로 화면을 이동합니다.

입체 보기에서는 드래그로 카메라를 돌리고 클릭으로 타일을 선택합니다. 오른쪽 위의 ↶/↷ 버튼은 시점을 45도씩 회전하며, 가운데 초기화 버튼은 기본 방향과 전체 보기로 돌아옵니다. 카메라 조작은 타일의 좌표·회전과 프로젝트 파일을 변경하지 않습니다.

## 파일과 저장

스테이지 파일은 편집 프로젝트이기도 합니다. 저장과 내보내기를 나누지 않고 `.esfile` 하나를 사용합니다. 외부 `stage.json`이나 챕터별 하위 폴더는 필요 없습니다.

```text
ErosionSector/                 ← 사용자가 선택한 작업 폴더
  tile/
    연구소/복도.nbt
    공장/복도.nbt
  stage/
    관측소.esfile
    지하수로.esfile
```

- `.esfile`은 ZIP 묶음이며 NBT를 포함하지 않습니다. 챕터·미션 이름과 설명은 묶음 내부에 저장됩니다. 구조의 자세한 내용은 [스테이지 파일 형식](docs/stage-format.ko.md)을 참고하세요.
- 타일은 `tile` 폴더를 기준으로 `연구소/복도.nbt`처럼 상대 경로로 참조합니다. 같은 이름의 다른 타일셋 파일을 대신 연결하지 않습니다. 확인용 SHA-256으로 같은 경로의 내용 변경도 검사합니다.
- ‘타일 폴더 연결’에서 `tile` 폴더를 선택하면 경로를 자동으로 기록하고 불러온 스테이지의 원본도 다시 연결합니다. 단일 NBT로 가져왔다면 타일 속성에서 `타일셋/타일이름.nbt` 경로를 지정해야 저장할 수 있습니다.
- 폴더 선택은 Chrome·Edge·Firefox의 디렉터리 파일 입력을 사용합니다. 이 기능은 선택한 파일을 읽으며, 작업 폴더에 직접 쓰는 기능은 아직 없습니다. 스테이지 저장은 다운로드 방식이므로 `stage` 폴더에 저장하세요.
- 원본이 없어도 설정은 열고 편집할 수 있습니다. 연결 전에는 경고를 표시하고 타일 저장 범위 전체로 충돌을 검사합니다. 원본 연결 후 실제 블록 점유로 다시 검사합니다.
- 모든 파일은 브라우저 안에서 읽으며 서버로 업로드하지 않습니다. 작업 중 읽은 원본은 브라우저 자동 저장에 캐시될 수 있지만 `.esfile`에는 원본·base64·점유 비트맵을 넣지 않습니다. 공유하려면 스테이지 파일과 필요한 외부 타일 폴더를 함께 전달하세요.
- 자동 저장 공간은 주소·브라우저별로 다르며 브라우저 데이터 삭제의 영향을 받습니다. 중요한 작업은 .esfile로 저장하세요.
- 지원 한도: NBT 원본 24MB, NBT 압축 해제 64MB, 타일 각 축 256블록, 타일 폴더 NBT 합계 64MB·200개, 배치 1000개, 기믹 3000개. 스테이지는 파일·압축 해제 설정 합계 각각 64MB 이하입니다.

## 현재 범위

이 버전은 스테이지 제작 앱입니다. Minecraft 안에서 스테이지를 생성하거나 기믹을 실행하는 로더는 아직 구현하지 않았습니다. 기본 예시에는 실제 건축물 NBT가 없습니다.

Erosion Sector 0.3.31의 `erosionsector:door_drive`와 `erosionsector:security_door_drive`는 천장 구동부입니다. 각 타일 외곽에서 같은 종류·방향의 구동부 행을 하나의 연결구로 읽습니다. NBT의 Width/Height로 소형 4×4, 중형 6×4, 대형 10×6을 구분합니다. 구동부 행에서 Height−1칸 아래가 문의 하단입니다. 프레임은 양옆 1/4, 위쪽 3/8블록이고 바닥 턱은 없습니다. `mount: ceiling`, 프레임 규격과 문 설정을 보존합니다. 보안 문은 중앙에서 좌우로 열리며, 별도 조건이 없으면 20틱(1초) 상호작용으로 개방합니다. 알람·터미널 조건을 지정했다면 조건 충족이 먼저 필요하며 폐쇄는 터미널·기믹 전용입니다. 자동 닫힘은 없습니다. 조건 없음은 `access: HOLD`로 저장하며, 게임에서 `/erosionsector door set <좌표> access none`으로 지정할 수 있습니다.

연결구를 수동으로 편집할 수도 있습니다. 방향·높이 및 문 종류/개폐 조건/파괴 규칙/빛·소음 속성은 `ports[].doorSettings`에 보존합니다. 문 속성 설정은 현재 게임의 `/erosionsector door set`에서 하며, 웹의 연결구 편집 화면에서 각 면의 문 종류·접근 조건·알람 시간·터미널 명령을 지정합니다. 양쪽의 접근 조건이 달라도 종류·크기·위치가 맞으면 연결됩니다. 게임의 스테이지 로더는 후속 작업입니다.

모드 블록의 데이터는 원본 NBT 바이트로 보존하지만, 실행 환경의 모드 설치 여부나 Create 장치의 회전·작동을 웹 앱에서 검증하지는 않습니다. 실제 게임에서 모방 패널 재질과 회전, 연결 장치를 테스트해야 합니다.

WorldEdit `.schem`과 Litematica 파일은 지원하지 않습니다. 먼저 Create 또는 바닐라 구조물 `.nbt`로 내보내세요. 편집기는 코드/명령 실행 기능을 제공하지 않습니다.

## 로컬 실행

Node.js가 있는 환경에서 이 폴더를 열고 실행합니다. 앱 실행 자체에는 의존성 설치가 필요하지 않습니다.

```powershell
node server.mjs
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다.

## 개발 검증

```powershell
npm install
npm test
npm run test:browser
```

브라우저 테스트는 로컬 서버가 실행 중이어야 하고 설치된 Microsoft Edge를 사용합니다. 테스트 결과와 화면 캡처는 추적하지 않는 `artifacts/` 폴더에 저장합니다. 배포 파일은 `dist/`의 HTML/CSS/JavaScript뿐입니다.

검증 범위: 입체 공간 충돌, 복층 수평 문 연결, 회전 좌표, NBT 원본 보존 및 비정상 파일 거부, 실제 브라우저의 배치·기믹·저장·복원·작은 화면 조작.

## 큰 스테이지의 계산과 그리기

문 연결은 위치·방향·크기로 후보를 좁혀 비교합니다. 기존 0.001블록 미만 오차 허용과 결과 순서는 유지합니다. 겹침 검사에서는 각 배치의 회전된 범위를 한 번 계산해 재사용합니다. 전체 겹침 쌍 비교는 여전히 배치 수의 제곱에 비례합니다.

평면도 문 연결망은 프로젝트를 수정할 때 갱신하며 마우스 이동·화면 이동에는 재사용합니다. 마우스 이동이 한 프레임 안에 여러 번 발생하면 한 번만 그립니다. 입체 보기에서 표시하지 않을 작은 라벨은 가림 검사를 건너뜁니다.

`npm run benchmark`는 타일 100·500·1000개인 직선 복도에서 문 연결과 전체 검사를 각각 7회 측정하고 중앙값을 출력합니다. 실제 편집기 렌더링이나 게임 FPS를 측정하지는 않습니다. 경계 오차·음수 좌표·회전·중복 연결에 대해 기존 전수 비교와 결과가 같은지 자동 검사합니다.

## 내부 이름과 파일 형식

모드 ID와 명령어는 `erosionsector`, 편집·게임 공용 스테이지는 `.esfile`(ZIP, `erosionsector-stage`, 버전 2)을 사용합니다. 이전 별도 프로젝트 파일과 JSON 스테이지 초안은 가져오지 않습니다. 게임 실행기는 아직 구현 전이므로 `runtimeReady: false`입니다.

## 자유 크기와 블록 점유

X/Z 배치와 이동은 1블록, Y 배치는 8블록 단위입니다. 화면의 큰 기준 격자는 16블록이며 좌표 입력은 X/Z 모두 블록 단위입니다. 파일의 기존 배치 좌표 단위와 별개로 스테이지의 `blockPosition`은 실제 블록 좌표를 기록합니다.

NBT 원본을 보존하고 공기·cave_air·void_air·structure_void를 제외한 모든 블록(모드 블록·액체 포함)을 점유 비트맵으로 기록합니다. 회전은 블록 중심을 기준으로 변환하고, 실제 블록끼리 충돌할 때 배치를 거부합니다. 층별 평면도에는 점유된 열을 표시하고 입체 보기는 여전히 타일의 저장 범위를 표시합니다. 타일 폴더를 연결하면 외부 원본 NBT에서 점유 정보를 다시 만들고 저장된 해시·크기를 대조합니다.

내보낸 스테이지의 `tileRules`는 높이 8의 배수·최소 문 하나·`non-air-only` 배치 정책을 지정합니다. 이후 게임 로더도 공기가 다른 타일을 지우지 않도록 이 정책을 지켜야 합니다. 현재 웹 앱은 실제 게임 월드를 생성하지 않습니다. 용량과 성능을 위한 파일·축 크기 한도는 기존과 같습니다.

## 0.3.35 반쪽 문

새 자동 설치 블록은 자기 타일의 두께 절반만 만듭니다. tile_door_drive / tile_security_door_drive 행과 tile_door_part 전체를 포함해 저장하세요. 편집기는 반쪽 본체 누락도 검사합니다. 위치·크기·종류가 같은 맞은편 문과 연결하며 양쪽의 접근 조건은 독립적으로 보존합니다. 실제 설계도에 연결된 문의 위치·크기·종류는 원본에서 읽고, 웹에서는 면별 조건과 이름·연결 필수 여부를 편집합니다.

일반 소·중형은 위로, 일반 대형은 위아래로 분리됩니다. 보안 소·중형은 좌우, 보안 대형은 위쪽 0도·시계 방향 120도·240도의 Y자 경계로 나뉜 세 조각이 각 구역 바깥으로 이동합니다. 프레임은 일반 소·중형 하단 1/8, 보안 소·중형 상하단 1/8, 대형 상하단 1/4이며 양옆은 모두 1/4블록입니다. 프레임과 동작은 연결구 메타데이터에 보존합니다.
